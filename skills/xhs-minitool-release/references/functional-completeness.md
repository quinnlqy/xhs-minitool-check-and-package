# 功能完整性与原生保存检查

适用于每次发布包回归及“页面按钮无法点击/小工具功能缺陷”排查。按当前项目功能选场景，记录不适用原因；无存档的工具无需添加钱包或存储桥接。不能为让测试通过放开解锁、删掉功能或改变玩法。

## 先锁定证据与覆盖范围

记录用户确认的运行包、ZIP SHA-256、入口、审核原文、步骤与未知项。没有审核录屏/具体按钮时继续独立排查，但保持审核根因“未确认”。对照各平台最近实际交付包和独有修复，避免从旧源码全量重建后丢失已交付热修；仅更新小红书时不顺手改其他平台包。

在最终 ZIP 的实际解压副本上执行以下不同路径，报告不要合并成一个“完整流程通过”：

| 路径 | 操作与断言 |
| --- | --- |
| 首次空存档 | 新 context，主/备份/迁移来源确实为空；首页默认入口可理解。通过真实点击、触摸、拖动完成各关键阶段，观察阶段进度/输出变化，直到首次保存或结算。按玩法验证重载后的结果；不能预塞钱包、解锁或完成状态 |
| 已有进度/旧档 | 保留余额、解锁、收据与旧字段迁移；覆盖首次流程尚未开放的不同交互、配方/关卡、购买与解锁。练习等非进度模式不应改进度 |
| 页面与生命周期 | 设置展开/收起、帮助、暂停/恢复、参考图、确认放弃、结果、欣赏、返回、再次进入；按实际产品列入口，不将不存在的功能列为失败 |
| 屏幕与宿主 | 竖屏、短竖屏、短横屏、桌面/平板适用布局；旋转、安全区变化、真实拦截点击的宿主导航占位；所有关键按钮和滚动入口可达 |
| 宿主故障与恢复 | 原生版本/能力、读取、保存等实际依赖分别注入故障；保留健康对照，不用“没有 SDK 的浏览器降级”代替支持原生存储的路径 |

每个制作/处理阶段至少有实际业务输出断言，例如覆盖变化、工具产生对象、库存变化、计算结果或保存记录。仅切换标签/阶段不证明该阶段功能可用；无需为了验收强求满分作品。不同交互分支按功能分别覆盖，不要求每款内容机械重复所有相同动作。

## 按钮可点的判定

1. 确认可见性、启用状态及条件。锁定、余额不足和暂停期间暂禁用可属于正常规则；用户是否看得懂前置条件和默认入口是否落在不可操作条目，另作引导问题记录。
2. 按设计滚动到按钮，再查可视范围、裁剪祖先和 elementFromPoint。预期弹窗遮住底层、可滚动区域外的按钮，与真实无法触达分别记录；不能仅看截图或盲升 z-index。
3. 发真实 tap/click，验证实际 click 或业务状态，而不是只看自动化动作返回成功。弹窗关闭后的异步恢复要等到真实 enabled，再点击并验证 pressed/下一视图；助手发现 disabled 就跳过，不能记成功。不要用固定延时或直接执行 onclick 掩盖漏点。
4. 使用项目合理的轻微手指移动检查误取消点击；工具拖动另测连续跨区、pointer capture、取消、库存与撤销。具体像素和坐标按当前布局/交互选，不照搬其他项目测试常数。
5. 记录失败发生时的目标状态、命中元素、遮罩/弹窗、输入事件、页面错误、尺寸及阶段。怀疑测试焦点/时序干扰时隔离重跑并说明原因；不自动重试到成功后抹掉失败证据。

## 发布前新增交互回归

有相应功能时执行以下检查；没有暂停、内容开关或调试面板的项目标为不适用。

- **快速关闭与返回**：暂停/帮助/参考弹窗关闭后，立即打开退出确认，再选继续或取消退出；连续执行并验证工具/输入、计时与真实操作恢复。不要用等待周期状态同步的固定延时掩盖问题。若父页依赖延迟上报的 paused 状态，核对暂停归属与释放：退出确认只应释放自己拥有的暂停，不能漏恢复，也不能无条件解除后台或其他独立暂停。
- **实际触摸区域**：在最窄和最矮布局、旋转及安全区变化后，测 getBoundingClientRect，而非只读作者 CSS。响应式规则可能把声明的高度或最小高度缩小；按项目约定的最小触摸尺寸（例如44 CSS px）断言，滚动后检查命中并真实点击，不能只扩大透明区域造成邻近按钮重叠。
- **初始化先于兼容层**：在页面导航前移除待测 API，以覆盖模块依赖求值、顶层常量和首次目录构建，而不只进入主函数后测试。兼容模块在入口文件中出现不证明先执行，依赖可能先使用 Object.fromEntries 等新 API；引导路径改用基线 API 或确保兼容层先执行。断言应用实际可操作，不能把错误诊断页出现当启动成功。
- **用户要求隐藏内容**：同时检查目录、订单/随机选择、快捷入口和直接进入路径；已有解锁/完成/余额记录按用户要求保留，隐藏不等于清档。保留规范化依赖的元数据，防止过滤目录后读取缺失项崩溃。不要把一次隐藏特定内容的决定带到其他项目。
- **正式去调试**：检查页面入口、URL/本地环境快捷开关、调试全局对象和模拟接口；在最终 ZIP 真实启动并尝试相关参数，确认不能绕过正式前置条件。必要错误诊断不属于调试作弊按钮；仅剩无效 CSS 选择器或注释不能直接当可用调试入口。

每个场景记录“触发 → 可观察机制 → 修复 → 失败前/修复后操作 → 未知”。这些经验来自受控环境复现，不说明它们就是某次泛化审核拒绝的原因。

## 原生持久化故障矩阵

适用于保存、购买、解锁、领奖、提交结果等关键写入。原生 SDK 的返回结构、读写一致性和支持版本以接口合约为准；不要将下表夹具当成官方宿主实际故障证明。

| 夹具 | 通过条件 |
| --- | --- |
| 健康写入 | 操作结果、权威记录和重新进入后的业务结果一致；只提交一次 |
| 主写拒绝 | 保留旧记录，不先显示到账/拥有；等待状态退出，可重试或返回 |
| 主写永不返回 | 有界等待与可操作的失败/重试状态；不自动清档或无声切换空后端 |
| 超时后迟到成功 | 超时不代表取消底层写；未结束的旧写跨存储实例保持同键保护。重试先重新读取，用收据/已拥有状态识别已提交，不能并发写出过时钱包、重复扣款或发奖 |
| 返回成功但未落盘 | 按合约回读或使用持久化完成信号确认，识别丢写；不能仅以 resolve、缓存、按钮文案变更判成功。若接口允许读取滞后，按文档做有界确认，不自行假设强一致 |
| 主写成功、备份拒绝/挂起 | 备份不无限阻塞已确认的主提交，也不让用户重复支付。备份同键串行，合并待写最新值，防止旧备份迟到覆盖新备份；不一律删掉备份功能 |
| 连点、换目标与重建实例 | 原事务保存最初目标，提交串行/幂等；重复实例不能绕过未完成写保护。会话内保护不能冒称跨进程或整页重载后的原子保证 |
| 读取/迁移异常 | 空档、损坏、无法读取分开；权威读失败不写空档，可选旧来源不可读不阻塞已确认有效的原生档；后端选定后迟到能力结果不改写另一处 |

至少从实际购买/解锁按钮和实际首次完成/结算入口检查适用故障，验证失败后的真实恢复，而非仅测底层存储函数。精确断言金额、库存、解锁、收据或当前项目的对应结果；不得把其他项目的键名、固定超时、价格、关卡或免费规则带到新项目。

## 报告边界

分别保留空存档实际流程、已有进度专项、布局命中和宿主故障恢复的证据，绑定同一最终 ZIP SHA-256。失败前/修复后报告分开，旧哈希报告不能算新包通过。列出实际动作、预期/观察结果和未覆盖功能；检查数量只作索引。

结构扫描、脚本 smoke、真实制作、受控桥接夹具、官方模拟器、Android 真机、iOS 真机和审核结果分别报告。一个层面通过不替代另一层面。没有真机/官方工具时，完成可运行部分并明确待验证，不宣称审核缺陷已解决。
