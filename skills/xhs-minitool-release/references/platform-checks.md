# 平台规则核对与历史保守配置

先尝试[当前官方文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)。下面是独立发布检查摘要，不是官方手册、最新能力表或审核承诺。

## 每次任务核对

| 项目 | 要确认的事 |
| --- | --- |
| ZIP 入口 | 当前是否要求根 index.html、单一 HTML、允许的文件类型与体积；压内容而不是外套目录；无依赖目录/映射/配置垃圾 |
| 资源与脚本 | 相对路径、大小写、所有资源随包；外链、模块、动态 import、内联脚本、worker 等是否符合当前宿主 CSP；不要根据普通浏览器可用推断宿主允许 |
| JavaScript/CSS | 宿主支持的旧内核基线；转译语法之外检查实际使用的新 API、dialog、布局单位等；选择局部回退 |
| 原生能力 | 当前 SDK 注入方式、客户端版本、具体方法、Promise/回调、返回结构与异常；按官方语义处理，不直接猜底层 bridge |
| 存储 | 空记录、格式、配额、读写一致性、迁移和持久化边界；关键数据权威来源固定，失败不换空档 |
| 交互与布局 | 宿主栏/按钮实际区域、安全区、横竖屏和短屏；滚动与拖动仲裁，弹窗打开/关闭后输入恢复 |
| 图形性能 | 项目实际使用的 WebGL/渲染能力；压力和后台恢复按功能测，不能把桌面帧率当手机预算 |

联网核心、服务器依赖或平台不支持能力无法仅靠 ZIP 消除，需说明具体阻塞。文档不可读时保留未知项，不虚构“已核对官方”。

## 打包脚本的默认规则

`package_release.py` 自带历史保守配置：单根 index.html、经典外置 JS、相对资源、无 iframe/自定义 CSP；后缀允许 HTML/CSS/JS/JSON、常见图片和 WOFF/WOFF2。ZIP 默认上限 10 MiB、建议 2 MiB，文本/Base64 阈值是工具提醒。这些是可追溯的本地检查配置，不是本日官方保证。

用 `--rules` 覆盖 JSON 支持的后缀、大小阈值与项目调试符号；仅依据已确认的当前规则调整。其他结构政策若变化，应审查并修改检查器与正反例，不能靠更改阈值绕过。

例如确认后加入项目调试符号：

```json
{"debugPatterns":["__INTERNAL_DEBUG_PANEL__","grantTestBalance"]}
```

正则只做线索：库字符串、注释和不可达分支可能误报；检查实际代码/调用路径并记录结论。静态解析不能完整覆盖动态资源、复杂 srcset、运行时网络和所有 CSS/JS 语义。
